# Proposal: Phase 2 用户体系 & 体验打磨

## 动机
Phase 1 完成了基础视觉打磨，但用户体系薄弱、缺少社交归属感、加载体验生硬：
- 个人中心仅显示手机号，无法编辑头像昵称，缺乏个人统计
- 后端收藏 API 已实现但前端未接入，收藏闭环缺失
- 所有列表加载都是空白 spinner，没有骨架屏占位
- 路线卡片难度无视觉区分，不同难度路线看起来一样
- 缺少下拉刷新和触觉反馈，交互感生硬

## 变更内容

### 1. 收藏功能（优先级最高）
- **三入口**：路线详情页、发现页卡片右上角、个人中心「我的收藏」
- **心形图标 + 收藏数**：未收藏灰色空心 → 收藏后红色实心 + 计数
- **后端**：复用已有 `POST /routes/{id}/favorite`，新增 `GET /routes/favorites` 获取收藏列表

### 2. 个人统计 + 头像昵称
- **ProfileHeader**：头像（支持拍照/选图上传）+ 昵称编辑
- **StatsPanel**：头像下方 3 指标并排卡片（总里程 / 总路线 / 总收藏）
- **后端**：新增 `GET /users/me` 获取用户信息 + 统计，`PUT /users/me` 更新用户资料

### 3. 难度配色区分
- 路线卡片左上角难度角标带颜色：easy=绿色 / medium=橙色 / hard=红色
- 卡片整体保持现有渐变色风格不变

### 4. 骨架屏 + 下拉刷新 + 触觉反馈
- **骨架屏**：发现页路线列表加载时 3 个灰色占位卡片 + 闪烁动画
- **下拉刷新**：发现页 + 个人中心列表 RefreshControl
- **触觉反馈**：开始记录、保存成功、删除确认等关键操作

## 影响范围
- **后端**：`users.py` 新增路由文件、`user.py` schema/model 扩展、`routes.py` 新增 favorites 列表端点
- **iOS**：`CityWalkApp.swift` ProfileView 重写、`ExploreView.swift` 收藏按钮 + 骨架屏 + 下拉刷新、新建 `SkeletonView.swift`、`Route.swift` +2 字段、`APIService.swift` +3 方法
